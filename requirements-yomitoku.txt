# --ocr-engine yomitoku: YomiToku 0.15's own dependencies, then YomiToku itself WITHOUT them:
#
#   pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126  # NVIDIA GPU; skip for CPU
#   pip install -r requirements-yomitoku.txt
#   pip install --no-deps --ignore-requires-python "yomitoku==0.15.*"
#
# Why not a plain `pip install yomitoku`: every YomiToku since 0.5.2 declares Python < 3.14, so
# pip on 3.14 quietly installs 0.4.1 (two years older, different models). Nothing in it breaks
# on 3.14 -- all 19 dependencies ship 3.14 wheels, and the yomitoku tests pass on 3.14.4 -- the
# cap is a declaration, raised by hand one release at a time (<3.13 in 0.5.2, <3.14 in 0.10.2).
#
# Left out of the list below, on purpose:
#   pypdfium2 -- YomiToku pins ==4.30.0, ocrmypdf 17.13 needs >=5. YomiToku only uses it in
#                load_pdf(); the plugin hands it page images, so ocrmypdf's 5.x is never touched.
#   onnxruntime -- imported by YomiToku, but any of the three builds provides the module. A venv
#                set up for --ocr-engine paddle already has one; plain `onnxruntime` on top of
#                onnxruntime-directml overwrites the DirectML build. Otherwise: pip install onnxruntime
#
